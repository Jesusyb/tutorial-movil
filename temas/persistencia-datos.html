💾 Persistencia y acceso a datos

Formas de guardar información en una app móvil para que no se pierda al cerrarla.

Definición

La persistencia de datos es la capacidad de una aplicación de guardar información de manera que siga existiendo aunque la app se cierre, el teléfono se reinicie o se quede sin batería. Lo contrario son los datos en memoria RAM (variables), que se pierden cuando termina el programa.

El acceso a datos son las técnicas y herramientas que usa la aplicación para leer, guardar, modificar y eliminar esa información (operaciones CRUD: Create, Read, Update, Delete).

Características

  • Durabilidad: la información permanece en el almacenamiento aunque se cierre la app.
  • Integridad: los datos se guardan completos y sin errores.
  • Consistencia: los datos cumplen reglas definidas (tipos, llaves, relaciones).
  • Disponibilidad: se puede consultar la información cuando se necesite, incluso sin internet si se guarda localmente.
  • Seguridad: la información sensible debe protegerse (cifrado, permisos).
  • Sincronización: en apps conectadas, los datos locales y los del servidor deben coincidir.

Formas de persistencia en dispositivos móviles

📄 Archivos

La app guarda información directamente en archivos (texto, JSON, imágenes, etc.).

  • Almacenamiento interno: privado para la app; se borra al desinstalarla.
  • Almacenamiento externo / compartido: para archivos que el usuario puede ver, como fotos o documentos descargados.
  • Preferencias (clave-valor): archivos pequeños para configuraciones, por ejemplo SharedPreferences o DataStore en Android y UserDefaults en iOS.

🗄️ Bases de datos locales

Se guarda la información de forma estructurada dentro del propio dispositivo. La más usada es SQLite, una base de datos relacional ligera que no necesita servidor. También existen Room (Android), Core Data (iOS) y Realm. Sirven para muchos registros que se consultan con filtros, por ejemplo una lista de tareas o un inventario.

☁️ Bases de datos remotas mediante servicios web

Los datos están en un servidor en internet y la app se comunica con él a través de un servicio web (API REST que normalmente responde en JSON). La base de datos puede ser MySQL, PostgreSQL, MongoDB, etc. También hay servicios listos como Firebase Firestore. Se usa cuando la información debe compartirse entre usuarios o dispositivos, como en una red social o la app de un banco.

Mecanismos de control de acceso a medios persistentes

Biblioteca de clases

Son las clases que ya trae el lenguaje o la plataforma para trabajar con archivos y flujos de datos. En Java/Kotlin para Android se usan File, FileInputStream, FileOutputStream, BufferedReader, y métodos del Context como openFileOutput() y openFileInput().

kotlin
// Guardar y leer un archivo en el almacenamiento interno
openFileOutput("notas.txt", Context.MODE_PRIVATE).use {
    it.write("Hola mundo".toByteArray())
}

val texto = openFileInput("notas.txt").bufferedReader().use { it.readText() }

Clases de SQLite

Android incluye clases para manejar SQLite directamente:

  • SQLiteOpenHelper: crea la base de datos y controla sus versiones (onCreate, onUpgrade).
  • SQLiteDatabase: ejecuta las operaciones (insert, query, update, delete, execSQL).
  • ContentValues: guarda los pares columna-valor para insertar o actualizar.
  • Cursor: recorre los resultados de una consulta.
java
public class AdminBD extends SQLiteOpenHelper {
    public AdminBD(Context context) {
        super(context, "escuela.db", null, 1);
    }

    @Override
    public void onCreate(SQLiteDatabase db) {
        db.execSQL("CREATE TABLE alumnos(id INTEGER PRIMARY KEY AUTOINCREMENT, nombre TEXT, grupo TEXT)");
    }

    @Override
    public void onUpgrade(SQLiteDatabase db, int anterior, int nueva) {
        db.execSQL("DROP TABLE IF EXISTS alumnos");
        onCreate(db);
    }
}

// Insertar un registro
SQLiteDatabase db = new AdminBD(this).getWritableDatabase();
ContentValues valores = new ContentValues();
valores.put("nombre", "Ana");
valores.put("grupo", "142");
db.insert("alumnos", null, valores);

Mapeo relacional de objetos (ORM)

Un ORM convierte automáticamente las tablas de la base de datos en objetos (clases) del lenguaje, así no hay que escribir SQL a mano para todo. En Android el más usado es Room, que forma parte de Android Jetpack. Otros ejemplos son Realm, Core Data (iOS), Hibernate (Java) y Entity Framework (.NET).

  • @Entity: la clase que representa una tabla.
  • @Dao: la interfaz con los métodos de consulta.
  • @Database: la clase principal que une todo.
kotlin
@Entity(tableName = "alumnos")
data class Alumno(
    @PrimaryKey(autoGenerate = true) val id: Int = 0,
    val nombre: String,
    val grupo: String
)

@Dao
interface AlumnoDao {
    @Insert
    suspend fun insertar(alumno: Alumno)

    @Query("SELECT * FROM alumnos WHERE grupo = :grupo")
    suspend fun porGrupo(grupo: String): List<Alumno>
}

@Database(entities = [Alumno::class], version = 1)
abstract class EscuelaDB : RoomDatabase() {
    abstract fun alumnoDao(): AlumnoDao
}

Proceso de autenticación y consumo de servicios web

Cuando una app necesita datos de un servidor privado, primero debe comprobar quién es el usuario. Un proceso típico con tokens es:

  1. El usuario escribe su correo y contraseña en la app.
  2. La app envía esos datos por HTTPS al servicio web (por ejemplo POST /api/login).
  3. El servidor valida las credenciales y, si son correctas, responde con un token (por ejemplo un JWT u OAuth 2.0).
  4. La app guarda el token de forma segura en el dispositivo.
  5. En cada petición siguiente, la app manda el token en el encabezado Authorization: Bearer <token>.
  6. El servidor revisa el token y responde con los datos en formato JSON.
  7. La app convierte el JSON a objetos (con librerías como Gson o Moshi) y los muestra en pantalla.
  8. Cuando el token expira, la app pide uno nuevo o vuelve a mostrar el inicio de sesión.

También se puede usar un servicio de autenticación ya hecho, como Firebase Authentication, que permite iniciar sesión con correo, Google, Facebook, número de teléfono, etc.

Ejemplos

Ejemplo 1: guardar una preferencia (SharedPreferences)
kotlin
val prefs = getSharedPreferences("config", Context.MODE_PRIVATE)

// Guardar
prefs.edit().putBoolean("modo_oscuro", true).apply()

// Leer
val oscuro = prefs.getBoolean("modo_oscuro", false)
Ejemplo 2: consultar SQLite con Cursor
java
SQLiteDatabase db = new AdminBD(this).getReadableDatabase();
Cursor c = db.rawQuery("SELECT nombre FROM alumnos WHERE grupo = ?", new String[]{"142"});

while (c.moveToNext()) {
    Log.d("BD", "Alumno: " + c.getString(0));
}
c.close();
Ejemplo 3: consumir un servicio web con Retrofit
kotlin
interface ApiEscuela {
    @POST("login")
    suspend fun login(@Body datos: LoginRequest): LoginResponse   // regresa el token

    @GET("alumnos")
    suspend fun alumnos(@Header("Authorization") token: String): List<Alumno>
}

val api = Retrofit.Builder()
    .baseUrl("https://miservidor.com/api/")
    .addConverterFactory(GsonConverterFactory.create())
    .build()
    .create(ApiEscuela::class.java)

// Dentro de una corrutina
val respuesta = api.login(LoginRequest("ana@correo.com", "1234"))
val lista = api.alumnos("Bearer ${respuesta.token}")
