🔔 Servicios y notificaciones

Trabajo que la app hace sin que el usuario la esté viendo y cómo avisarle de lo que pasa.

Contenido

  2. ¿Qué son las tareas en segundo plano?

Definición

Un servicio es un componente de una aplicación que realiza operaciones de larga duración sin interfaz gráfica, como reproducir música, descargar un archivo o sincronizar datos. En Android hay tres tipos:

  • En primer plano (foreground): el usuario sabe que está funcionando porque muestra una notificación permanente (por ejemplo, un reproductor de música o el GPS de una app de mapas).
  • En segundo plano (background): hace trabajo que el usuario no nota directamente. Desde Android 8 tiene muchas restricciones.
  • Vinculado (bound): otros componentes se conectan a él para pedirle datos o acciones mientras dure la conexión.

Una notificación es un mensaje que la app muestra fuera de su interfaz, en la barra de estado o en la pantalla de bloqueo, para avisar al usuario de algo importante.

¿Qué son las tareas en segundo plano?

Son procesos que se ejecutan sin bloquear la interfaz o incluso cuando la app no está abierta. El hilo principal (UI) solo debe dibujar la pantalla; si se hace ahí algo pesado (internet, base de datos) la app se congela y aparece el error ANR (Application Not Responding).

Se dividen en:

  • Trabajo inmediato asíncrono: mientras la app está abierta, usando corrutinas de Kotlin o hilos (Thread, Executor).
  • Trabajo persistente: tareas que deben terminar aunque se cierre la app o se reinicie el teléfono, como subir fotos o sincronizar. Para esto se recomienda WorkManager.
  • Servicios en primer plano: tareas largas que el usuario está viendo, como una descarga o la música.
🔋 Los sistemas Android e iOS limitan las tareas en segundo plano (modo Doze, App Standby, Background App Refresh) para ahorrar batería, así que hay que usar las herramientas oficiales.

Tratamiento de notificaciones

  • Canales de notificación: desde Android 8.0 cada notificación debe pertenecer a un canal (por ejemplo "Mensajes" o "Promociones"), y el usuario puede activar o desactivar cada uno.
  • Permiso: desde Android 13 hay que pedir el permiso POST_NOTIFICATIONS. En iOS siempre se pide autorización al usuario.
  • Contenido: ícono, título, texto, imagen grande, estilo expandible y prioridad.
  • Acciones: botones como "Responder" o "Marcar como leído", y un PendingIntent que abre la app al tocar la notificación.
  • Notificaciones locales: las genera la propia app (un recordatorio o alarma).
  • Notificaciones push (remotas): las envía un servidor a través de Firebase Cloud Messaging (FCM) en Android o APNs en iOS, aunque la app esté cerrada.

Proceso de implementación

Proveedores de contenido (Content Providers)

Un Content Provider permite que una app comparta sus datos con otras apps de forma controlada, por ejemplo los Contactos o la Galería. Pasos:

  1. Crear una clase que herede de ContentProvider.
  2. Implementar los métodos onCreate(), query(), insert(), update(), delete() y getType().
  3. Definir una URI de contenido, por ejemplo content://com.ejemplo.escuela/alumnos.
  4. Registrar el proveedor en el AndroidManifest.xml con su android:authorities y permisos.
  5. Las otras apps acceden a los datos con un ContentResolver.
xml
<provider
    android:name=".AlumnosProvider"
    android:authorities="com.ejemplo.escuela"
    android:exported="true"
    android:readPermission="com.ejemplo.escuela.LEER" />
kotlin
// Leer los contactos del teléfono con un ContentResolver
val cursor = contentResolver.query(
    ContactsContract.Contacts.CONTENT_URI, null, null, null, null
)

Tareas en segundo plano (WorkManager)

  1. Agregar la dependencia de WorkManager al proyecto.
  2. Crear una clase que herede de Worker (o CoroutineWorker) y poner el trabajo en doWork().
  3. Definir las condiciones (Constraints): con internet, cargando, batería no baja, etc.
  4. Crear la solicitud: OneTimeWorkRequest (una vez) o PeriodicWorkRequest (cada cierto tiempo, mínimo 15 minutos).
  5. Encolarla con WorkManager.getInstance(context).enqueue().
kotlin
class SincronizarWorker(ctx: Context, params: WorkerParameters) : Worker(ctx, params) {
    override fun doWork(): Result {
        // Aquí va el trabajo pesado, por ejemplo subir datos al servidor
        return Result.success()
    }
}

val condiciones = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.CONNECTED)
    .build()

val solicitud = PeriodicWorkRequestBuilder<SincronizarWorker>(1, TimeUnit.HOURS)
    .setConstraints(condiciones)
    .build()

WorkManager.getInstance(this).enqueue(solicitud)

Notificaciones

  1. Declarar el permiso POST_NOTIFICATIONS en el manifiesto y pedirlo en tiempo de ejecución (Android 13+).
  2. Crear un canal con NotificationChannel (Android 8+).
  3. Construir la notificación con NotificationCompat.Builder.
  4. Agregar un PendingIntent para abrir la app al tocarla.
  5. Mostrarla con NotificationManagerCompat.notify().
kotlin
// 1. Crear el canal
val canal = NotificationChannel("tareas", "Tareas", NotificationManager.IMPORTANCE_DEFAULT)
getSystemService(NotificationManager::class.java).createNotificationChannel(canal)

// 2. Intent para abrir la app
val intent = Intent(this, MainActivity::class.java)
val pending = PendingIntent.getActivity(this, 0, intent, PendingIntent.FLAG_IMMUTABLE)

// 3. Construir y mostrar
val notificacion = NotificationCompat.Builder(this, "tareas")
    .setSmallIcon(R.drawable.ic_notificacion)
    .setContentTitle("Recordatorio")
    .setContentText("Tienes que entregar la práctica hoy")
    .setContentIntent(pending)
    .setAutoCancel(true)
    .build()

NotificationManagerCompat.from(this).notify(1, notificacion)
